# Online Payment Fraud Detection

A beginner-friendly Machine Learning mini project that predicts whether an online payment is **Genuine (0)** or **Fraudulent (1)**.

## Tools and technologies

- **Python:** Main programming language.
- **VS Code:** Code editor used to write and run the project.
- **Pandas:** Creates and manages transaction data in table form.
- **Scikit-learn:** Provides the machine learning algorithm and evaluation tools.
- **Random Forest Classifier:** Learns patterns and predicts the transaction class.
- **CSV:** Stores the generated sample transaction dataset.

## Project features

The model uses six input features:

1. Amount — transaction value in rupees.
2. Time — hour of the transaction (0–23).
3. Location change — 0 means no, 1 means yes.
4. Recent transactions — number of recent transactions.
5. Device change — 0 means no, 1 means yes.
6. Failed attempts — number of failed login/payment attempts.

Output:
- 0 = Genuine transaction
- 1 = Fraudulent transaction
- Fraud probability = estimated probability produced by the model.

## How to run in VS Code

1. Install Python 3 and VS Code.
2. Open this project folder in VS Code.
3. Open Terminal → New Terminal.
4. (Recommended) Create a virtual environment:

   Windows:
   ```bash
   python -m venv .venv
   .venv\Scripts\activate
   ```

5. Install the required libraries:
   ```bash
   pip install -r requirements.txt
   ```

6. Run the project:
   ```bash
   python app.py
   ```

The program creates `transaction_data.csv`, trains the model, displays evaluation scores, and asks you to enter a new transaction.

## Example input for demonstration

Try a suspicious-looking transaction:

- Amount: 8000
- Time: 2
- Location changed: 1
- Recent transactions: 10
- Device changed: 1
- Failed attempts: 3

Then try a normal-looking transaction:

- Amount: 500
- Time: 14
- Location changed: 0
- Recent transactions: 2
- Device changed: 0
- Failed attempts: 0

The exact probability and prediction are generated by the trained model.

## Workflow

Transaction data → Feature selection → Train/test split → Random Forest training → Model evaluation → New transaction prediction

## Important limitation

The dataset is synthetic (computer-generated) and is created for classroom demonstration. The model learns labels generated using simple teaching rules. Its scores are not evidence of real-world banking accuracy. A real payment system needs a large, representative, secure, real-world dataset and careful testing.
